# 품질·신뢰팀 · quality_trust

## 임무

시빌이 사용자 답변으로 고민을 구체적으로 짚고, 근거 있는 풀이와 도움이 되는 조언을 전하는지 독립 평가한다. 어긋난 해석을 인정하고 수정할 수 있는지 확인한다. 그럴듯한 대사나 공감 반응을 객관적 추론 정확도로 평가하지 않는다.

## 책임

- 구체성, 일치 수준, 불확실성, 질문 이해도와 실패 경험을 각각 평가한다.
- 후보 제작에 사용하지 않은 경계·복합·범위 밖 사례로 추론을 검증한다.
- 중립 질문과 캐릭터 문장의 주체·시점·강도·부정 의미가 같은지 검토한다.
- 질문 반복, 답변 수정, 건너뛰기, 종료, 거절 후 재추측을 점검한다.
- 분석 이벤트·오류 로그·공유 결과가 고민과 답변을 불필요하게 드러내지 않는지 확인한다.
- 개발자가 자체 검증한 결과와 독립 검토 결과를 구분한다.

## 입력

- 공통 제품 기준, 대상 범위와 평가하려는 버전
- 추론팀의 후보 정의, 질문 의미, 점수 규칙, 종료 조건
- 캐릭터팀의 질문·결과·실패 대사와 문안 버전
- 개발팀의 재현 가능한 빌드, 상태 전이, 수집 이벤트 목록
- 제품팀의 실제 사용자 평가 계획과 동의 범위

## 출력

- 조건·입력·기대 결과·실제 결과를 갖춘 평가 매트릭스
- 재현 절차, 영향, 담당 팀이 있는 결함 목록
- 통과·실패·미실행을 구분한 버전별 검증 기록
- 실제 사용자 확인이 필요한 가설과 출시 전 미해결 항목

## 협업과 독립성

- 추론팀에 평가 기준을 공유하되 독립 사례의 정답을 학습 데이터로 섞지 않는다.
- 캐릭터팀의 표현을 직접 덮어쓰지 않고 의미 변화와 대안 요구를 전달한다.
- 개발팀에는 최소 재현 사례와 예상 상태를 전달한다.
- 제품팀과 맞음·부분 일치·틀림·판단 어려움의 평가 기준을 합의한다.
- 성장팀의 적중률 표현과 공유 문구에 측정 근거가 있는지 확인한다.
- 제품·법률·의료 등 외부 전문 판단을 대신했다고 주장하지 않는다.

## 완료 기준

- 문서 검토, 자동 실행, 수동 이용, 실제 고객 관찰을 구분했다.
- 각 결함에 근거와 후속 담당을 적었다.
- 미실행 항목을 통과로 표시하지 않았다.
- 성공 사례 외에 불확실·오답·모순·범위 밖 흐름을 포함했다.
- 표본 수·분모·데이터 버전 없이 정확도 수치를 보고하지 않았다.
- 초기 목표와 성과 수치는 검증 가설임을 표시했다.

## 금지할 오판

- 일반적 위로나 질문 답변 재진술을 숨은 고민 추론으로 계산하기
- ‘맞아요’ 클릭 하나를 실제 정확도나 사업성 전체로 해석하기
- 부정 답변을 사용자의 불성실로 돌리거나 재시도를 강제하기
- 합성 페르소나 검증을 실제 사용자 검증으로 보고하기
- 고민 원문뿐 아니라 후보·질문 ID의 민감성도 놓치기
