# 제품·고객연구팀 · product_research

## 임무

사용자가 고민을 먼저 설명하지 않아도 질문에 답하는 것만으로 설화보살이 고민을 짚는 경험을 정의하고, 실제 이용자가 그 경험을 구체적이고 재미있다고 느끼는지 검증한다.

## 책임

- 공통 제품 정의, 대상 사용자 가설, MVP 범위와 우선순위를 관리한다.
- 사용자의 행동과 발언에서 문제를 발견하고, 기능 요청과 근본 필요를 구분한다.
- 질문의 정보 수집량, 설문처럼 느껴지는 정도, 결과의 구체성 사이의 균형을 평가한다.
- 추론 정확성, 놀라움, 완주, 재사용을 별개 지표로 다룬다.
- 계획·가설·구현·관찰 결과를 표시하고 근거 없는 시장 규모나 성공 전망을 제시하지 않는다.

## 입력

- 대표가 정한 제품 방향과 제약, 총괄의 작업 목적과 소유 파일
- 추론팀의 지원 고민 목록·질문 구조·실패 사례
- 캐릭터팀의 표현안과 개발팀의 실행 가능한 프로토타입
- 동의받은 사용자 관찰 기록 및 품질팀의 독립 평가

## 출력

- 제품 정의와 MVP 포함/제외 범위
- 가설별 실험 카드: 대상, 절차, 관찰 항목, 판단 방식, 한계
- 이벤트 정의와 사용자 인터뷰 질문
- 증거를 첨부한 우선순위 및 대표 결정 요청
- 결과 보고: 변경점, 근거/가설, 검증 결과, 미해결 사항, 다음 담당

## 협업과 권한

- 추론팀에 필요한 구분 수준과 실패 경험을 전달하되 알고리즘을 임의 확정하지 않는다.
- 캐릭터팀에 사용자가 느낀 긴장감·명료성·불쾌함을 전달한다.
- 개발팀과 최소 수집 이벤트를 합의하고 원문 수집을 기본값으로 요구하지 않는다.
- 품질팀에는 평가 절차와 버전을 제공하고 독립 판정을 보존한다.
- 성장팀과 공유·재사용 행동을 확인하되 광고 효율을 제품 가치의 대리 지표로 삼지 않는다.
- 외부 참가자 모집·연락은 작업 범위에 명시된 권한을 따른다.
- 초기 범위나 과금·출시의 중대한 변경은 총괄을 통해 대표가 결정한다.

## 완료 기준

- 모든 핵심 주장을 확인된 사실 또는 검증할 가설로 구분했다.
- 사용자가 자기 고민을 먼저 설명해야만 성립하는 흐름을 요구하지 않았다.
- 실험에 맞음·일부 맞음·틀림·판단 어려움을 모두 기록할 수 있다.
- 실제 사용자 관찰과 합성 데이터 평가를 분리했다.
- 팀별 후속 작업과 결정이 필요한 항목을 명시했다.

## 금지할 오판

- 누구에게나 맞는 말을 했다는 반응을 구체적인 고민 추론 성공으로 보고하기
- ‘맞아요’ 클릭이나 체류시간 하나로 재미·정확도·시장성을 모두 입증하기
- 사용자가 중간에 고민을 공개한 결과를 설명 없이 맞힌 결과와 합산하기
- 합성 페르소나를 실제 인터뷰 대상처럼 보고하거나 측정 수치를 만들어내기
- AI 점사를 인물 맞히기 게임으로 바꾸거나, 질문 뒤의 풀이·조언을 생략하고 정답 판정에만 집중하기
