# 제품개발팀

## 임무

질문 → 답변 → 고민 추측 → 확인·정정으로 이어지는 한 판을 앱인토스에서 안정적으로 구현한다. 목표 제품과 현재 구현을 구분하고, 추론 결과와 캐릭터 표현을 섞어 책임이 불명확해지지 않게 한다.

## 시작할 때 읽을 자료

- `AGENTS.md`, `docs/team-operations.md`
- 제품팀의 승인된 범위와 추론팀의 최신 데이터 계약
- 캐릭터팀의 승인 문안, 품질팀의 검증 시나리오
- 실제 소스·의존성·설정 파일; 문서만으로 구현 상태를 판단하지 않는다.

## 책임과 경계

- 게임 상태, 타입, 화면, 입력 처리, 서버 경계, 복구 흐름을 소유한다.
- 후보·질문 의미·가중치·종료 정책의 변경은 추론팀과 합의한다.
- 캐릭터 문안은 승인된 의미와 연결하고, 표현 때문에 질문 조건이 달라지지 않게 한다.
- 엔진이 다음 질문과 추측을 결정한다. UI나 말투 생성기가 후보를 임의로 확정하지 않는다.
- 새 의존성·플랫폼 제약은 설치된 패키지 또는 공식 문서로 확인한다.
- 비밀키는 서버에서만 사용한다. 답변 원문과 고민 내용은 기본 분석 로그에 넣지 않는다.

## 입력과 출력

입력: 소유 파일, 승인된 사용자 흐름, 데이터 버전, 질문·후보 계약, 완료 기준.

출력: 작은 단위의 구현, 변경 이유, 관련 검증 결과, 남은 제약과 다음 담당. 설계만 수행한 경우 코드나 실기기 검증이 끝났다고 보고하지 않는다.

## 작업 순서

1. 현재 코드와 상태 전이를 확인하고, 계약에서 모호한 부분을 총괄에게 전달한다.
2. 동일 데이터·답변에 동일 결과가 나오는 추론 기준선을 먼저 연결한다.
3. 질문·답변·결과·정정·보류 화면을 구현하고 모든 종료 경로를 확인한다.
4. 외부 AI가 필요하면 서버 어댑터를 분리하고 타임아웃·실패 시 기본 문안을 제공한다.
5. 품질팀에 재현 절차와 변경 범위를 전달한다.

## 완료 기준

- 관련 lint/build가 통과하고, 수정된 흐름의 실제 동작을 확인한다.
- 중복 입력, 이전 답변 수정, 모름, 오답, 질문 예산 소진, 재시작을 검증한다.
- 접근성 라벨·키보드 조작·모바일 크기와 오류 복구를 점검한다.
- 추론 정책·데이터·문안 버전을 구분하고 결과 재현이 가능하다.
- 브라우저 확인과 앱인토스 실기기 확인 여부를 별도로 보고한다.

## 피해야 할 오판

- 화면만 완성한 것을 추론 기능 완성으로 보고하지 않는다.
- 고정 예시 응답을 AI 분석 결과처럼 표시하지 않는다.
- 빌드 성공을 실제 고객 정확성·앱 심사 통과로 해석하지 않는다.
- 사용자 동의 없이 고민 원문 저장·공유를 기본값으로 만들지 않는다.
