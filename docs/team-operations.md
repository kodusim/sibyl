# 설화보살 팀 운영

## 공통 목표

최신 사용자 결정: 게임이 아닌 사주·점집 같은 AI 점사 서비스다. 질문은 내부 추론 수단이고, 마지막에 마음을 들여다본 듯한 풀이와 조언을 제공한다. 후속 선택은 한마디 조언·선택 풀이·상세 점사 구상이며 광고·결제 형식은 앱인토스 전문팀 검토를 거친다.

질문 답변을 바탕으로 사용자의 마음과 고민을 짚고 무당처럼 풀이와 조언을 주는 점사 경험을 검증한다. 성공을 전제하지 않고 정확성·몰입·오답 경험을 실제 사용자에게 확인한다.

## 역할과 실행

대표는 사용자, 총괄은 루트 에이전트다. 일곱 팀은 각각 `agents/`의 역할 지침과 `docs/team-deliverables/`의 첫 설계를 갖는다. 역할 문서를 만든 것과 상시 실행 중인 프로세스는 다르다. 작업마다 필요한 담당을 실행하고 산출물을 검토한다.

현재 세션은 총괄을 포함해 최대 4개 에이전트가 동시 실행 가능하므로 담당을 최대 3개씩 나누어 작업한다. 완료된 담당에게 후속 작업을 전달하거나 새 세션에서 역할 문서를 읽혀 재구성한다.

## 작업 요청 양식

```text
담당: 역할 파일 경로
목적: 사용자 경험 또는 해결할 문제
입력: 공통 기준, 선행 산출물, 확인된 사실
소유 파일: 수정 가능한 정확한 경로
산출물: 검토 가능한 결과
완료 기준: 동작/문서/평가 기준
제약: 이번 작업에서 제외할 범위
```

결과 보고는 변경 파일, 검증 결과, 가설과 한계, 다음 담당 순서로 작성한다. 총괄만 공통 기획과 작업 우선순위를 통합한다.

## 첫 개발의 순서

1. 제품팀: 첫 사용자·고민 범주·완료 경험의 가설 정리
2. 추론팀 + 콘텐츠팀: 후보와 질문 의미를 확정하고 말투를 연결
3. 개발팀: 합의된 데이터 계약으로 질문 → 답변 → 점사와 조언 → 선택적 추가 풀이 흐름 구현
4. 품질팀: 모순·불확실·범위 밖 고민·오답을 독립 검증
5. 제품팀 + 성장팀: 실제 사용자 검증 후 공유·재이용 실험

팀별 첫 산출물은 제안이며 승인된 구현 사양이 아니다. 범주, 질문 수, 성과 목표, 과금은 통합 검토 후 결정한다. 추론·콘텐츠·개발 문서 간 스키마 차이가 있으면 추론팀의 의미 정의를 바탕으로 총괄이 단일 계약을 확정한다.

## 이번 작업의 범위

기존 여섯 담당에 앱인토스 전문팀을 추가하고 최신 점사 방향을 반영한다. 점사 기능 구현·실사용 검증·앱 출시와 구분한다. 현재 코드는 이전 상담 데모 상태다.

## 설립 결과

여섯 담당 에이전트를 실제로 실행했고 각 담당이 역할 지침과 초기 산출물을 작성했다. 총괄은 여섯 산출물을 검토했다. 품질팀의 독립 검토 범위는 제품·추론·콘텐츠 초기 설계이며 개발·성장 후속 문서 전체 검증과 구분한다.

## 통합 검토와 다음 작업

| 우선순위 | 작업 | 주 담당 | 완료 조건 |
| --- | --- | --- | --- |
| P0 | 플랫폼 등록·심사·수익화 검토 | 앱인토스 + 품질 + 성장 | 공식 정책과 미확인 사항 구분, 등록과 출시 구분 |
| P0 | 첫 후보 범위 제안 통합 | 제품 + 추론 | 후보 포함·제외 기준과 범위 밖 처리 명시 |
| P0 | 단일 데이터 계약 확정 | 추론 + 개발 | 답변·건너뛰기·수정·추측·일부 일치·종료 의미 합의 |
| P0 | 질문·결과 평가 세트 작성 | 추론 + 품질 | 결과를 직접 묻는 문항과 근거 없는 추측을 구별 |
| P1 | 점사 프로토타입 구현 | 개발 + 캐릭터 | 고민 원문 입력 없이 질문부터 점사·후속 풀이·종료까지 이용 가능 |
| P1 | 독립 검증 후 실제 사용자 파일럿 | 품질 + 제품 | 합성 결과와 사용자 반응을 분리해 보고 |
| P2 | 공유·재이용 실험 | 성장 + 제품 | 개인 고민 노출 없이 실제 행동 측정 |

첫 설계의 질문 수와 파일럿 규모는 가설로 유지한다. 캐릭터팀의 예시 대화는 말투와 의미 보존의 예시이며, 적중하는 질문 데이터가 아니다. 내부 후보 점수를 사용자에게 실제 정답 확률로 표시하지 않는다.
