# 성장·사업팀 초기 설계

> 최신 사용자 방향 반영: 게임이 아닌 AI 점사 서비스다. 질문 뒤 고민을 짚는 풀이와 조언을 제공한다. 아래 기술·사업 설계는 미검증 초안이다. 서비스명은 ‘설화보살’, 소개 문구는 ‘마음을 짚는 AI 점집’으로 확정했다.

상태: 실험 제안. 실제 고객 검증, 광고 집행, 외부 연락, 과금은 수행하지 않았다. 현재 앱은 상담 데모이며 아래 점사 흐름과 이벤트는 미구현이다.

## 성장 가설

사용자가 고민을 설명하지 않았는데 구체적으로 짚고 풀이해줬다고 느끼면, 고민 내용을 드러내지 않고도 친구에게 점사를 권할 수 있다. 이는 검증 전 가설이며 성장률이나 사업 성공을 약속하지 않는다.

## 단계별 실험

| 단계 | 실험 | 판단할 증거 | 반증과 다음 행동 |
| --- | --- | --- | --- |
| 가치 검증 | 제품팀 파일럿에서 일반적 문구와 추론 결과의 구체성을 비교 | 분야·상황·갈등을 설명 없이 짚었는지, 완주와 불편 | 분야만 맞거나 설문처럼 느끼면 공유보다 질문·추론 개선 |
| 공유 | 결과 뒤 선택형 경험 공유 카드 제공 | 미리보기 열기, 공유 시도, 확인 가능한 완료, 초대 유입 | 클릭만 많고 전달·유입이 확인 안 되면 성공으로 집계하지 않음 |
| 재이용 | 다른 고민이 생겼을 때 다시 점사를 받을 이유 조사 | 자발적 재이용과 이유, 새 점사 열람 | 해석 수정 때문이면 실패 회복으로 분류 |
| 수익화 | 한마디 조언·선택 풀이·상세 점사의 이해·선호 조사 | 무료 점사와 추가 풀이의 차이를 이해하는지 | 불안 해소나 핵심 점사 공개를 인질로 느끼면 해당 안 수정 |

사용자 구상은 한마디 조언=짧은 광고, 선택 풀이=영상 광고, 상세 점사=유료 결제다. 플랫폼이 광고 길이와 형식을 이대로 지원하는지, 결제 조건은 무엇인지 앱인토스 전문팀 검증 전이다. 첫 점사는 자체로 의미 있는 풀이를 주고 추가 이용은 선택으로 둔다.

실험의 성공 기준과 표본은 첫 기준선 측정 후 대표·제품팀이 사전 결정한다. 작은 파일럿의 긍정 반응을 시장 전체 수요로 일반화하지 않는다. 구현되지 않은 결제를 가능한 것처럼 보여주지 않는다.

## 공유 제안

- 기본 문구 초안: “말하지 못한 마음을 짚어주는 AI 점사.” 확정 서비스명은 별도로 반영한다.
- 개인 카드에는 사용자가 선택한 경우에만 질문 개수와 ‘맞음/일부 맞음’ 같은 평가를 포함한다.
- 고민의 분야·후보 ID·질문·답변·추측 원문은 기본 공유물에서 제외한다.
- 공유 전에 미리보기와 취소를 제공하고 자동으로 게시하지 않는다.
- 틀린 결과를 맞혔다고 꾸미거나 전 사용자의 적중률처럼 표현하지 않는다.
- 초대 링크는 출처 버전 정도만 구분한다. 고민 추정값을 URL에 넣지 않는다.
- 앱인토스에서 가능한 공유 방식과 완료 신호는 개발팀이 공식 자료로 확인한다. 현재 지원을 가정하지 않는다.

## 이벤트 초안

| 이벤트 | 최소 속성 | 해석 |
| --- | --- | --- |
| reading_started | 실험·앱 버전 | 시작 세션 분모 |
| reading_presented | 질문 개수, 결과 상태 | 점사 열람·보류 구분. 중단은 별도 이벤트로 집계 |
| result_feedback | 맞음/일부/틀림/판단 어려움 | 사용자 평가이며 객관 정확도와 별개 |
| share_preview_opened | 카드 버전 | 공유 관심 |
| share_attempted | 공유 방식 | 실행 시도이며 완료 아님 |
| share_completed | 확인 가능한 경우의 성공 신호 | 완료 신호 의미를 플랫폼별 검증 |
| reading_restarted | 직전 이용 종료 유형 | 같은 세션의 반복, 재방문 아님 |
| invite_opened | 비개인 출처 코드 | 유입이며 신규 사람 수 확정 아님 |

공통 속성은 세션 내 임시 식별자와 버전으로 제한하는 초안이다. 원문·민감 후보 ID·실명·연락처는 기본 수집하지 않는다. 구체적 보존 기간과 수집 범위는 개발·품질팀과 통합한다. 장기 재방문은 적절한 식별 방식이 없으면 측정 불가로 표시하고 같은 사람이라고 추측하지 않는다.

지표는 각 노출의 분모와 기간을 함께 기록한다. 이탈을 제외한 ‘적중률’, 공유 완료만 본 성공 사례, 반복 클릭의 중복 집계, 실험군 구성이 다른 단순 전후 비교를 피한다.

## 비용·수익 모델 초안

실제 가격·수수료는 아직 확인하지 않았으므로 금액을 제시하지 않는다.

- 세션 변동비 = 추론 서버 사용량 + 언어모델 호출 수 × 호출별 입력/출력 사용량 단가 + 저장·전송·관측 비용
- 유료 거래 순수입 = 실제 결제액 − 적용 수수료 − 환불/취소액 − 거래에 귀속되는 비용
- 기간 손익 = 전체 순수입 − 무료·유료 전체 세션 변동비 − 고정 운영비 − 유입 집행비
- 고객 획득비 = 귀속 가능한 유입 집행비 / 정의된 신규 고객 수. 익명 유입만 알면 고객 획득비로 부르지 않는다.
- 비교 변수: 질문 수, 호출 재시도, 결과 재생성, 무료 재이용, 장애율, 사용자당 점사 수, 유료 전환, 환불.

언어모델 없이 검증용 질문·결과 템플릿으로 시작하는 안도 비교한다. 실제 공급자 선택과 단가 확인 후 낮음/기준/높음 사용량 시나리오를 계산한다. 아직 유료 기능·가격·광고 모델은 확정하지 않았다.

## 다음 담당과 미해결 사항

- 제품팀: 사용자 가치와 재이용 이유를 검증하고 단계 이동 근거 제공.
- 추론팀: 점사당 질문 수·보류·해석 수정 흐름의 측정 정의 제공.
- 캐릭터팀: 공유 초대 문구와 실패 결과 표현 검토.
- 개발팀: 최소 이벤트·공유 가능 기능·사용량 측정 계약 제안.
- 품질팀: 공유 데이터 노출, 과장된 적중 표현, 과금 압박 검토.
- 대표: 실제 모집·유료 실험·광고 집행 단계의 범위와 예산 결정.

미해결: 사용자가 실제로 공유하고 싶은지, 재사용할 새 고민이 있는지, 지원 범위와 비용이 유지 가능한지. 문서 검토만으로 답할 수 없으며 실제 실험 후 갱신한다.
