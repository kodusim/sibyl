# 제품·고객연구팀 초기 기획

> 최신 사용자 방향 반영: 게임이 아닌 AI 점사 서비스다. 질문 뒤 고민을 짚는 풀이와 조언을 제공한다. 아래 기술·사업 설계는 미검증 초안이다. 서비스명은 미확정이며 ‘신통 — AI 점집’은 후보명이다.

상태: 기획 가설. 실제 사용자 조사와 추론 성능 검증은 아직 수행하지 않았다.

## 제품 정의

시빌은 사용자가 고민을 먼저 설명하지 않아도, 질문에 대한 답변을 바탕으로 AI 무당이 마음을 짚는 점사와 조언을 전하는 서비스다. 점집을 방문한 듯한 경험이 중심이며 아키네이터는 내부 추론 방식의 참고다. 실제 독심술이나 미래의 확정을 제공하지 않는다.

사용자 가치 가설: ‘내가 자세히 말하지 않았는데 내 사정을 짚었다’는 놀라움과, 결과를 통해 자기 마음을 돌아보는 재미.

현재 구현: 고민 입력 후 주제별 고정 응답을 보여주는 상담 데모. 목표 흐름과 추론 엔진은 미구현이다.

## MVP 제안

- 입장 → 마음속 고민 떠올리기 → 선택형 질문 → 고민을 짚는 점사와 조언 → 선택적 추가 풀이.
- 점사 열람에 정답 확인을 요구하지 않는다. 해석이 어긋났다는 피드백과 수정 요청은 선택적으로 제공한다.
- 시작 화면에서 고민 원문이나 세부 범주 선택을 요구하지 않는다.
- 내부 후보는 일상적 관계·일/진로처럼 제한된 범위로 시작하되 범위 밖 고민을 인정한다.
- 범주만 맞히는 데서 끝나지 않고 상황 또는 갈등 원인까지 짚는 결과를 목표로 한다.
- 답변에는 불확실성을 표현할 선택지를 제공한다. 답을 바꾸거나 중단할 수 있게 한다.
- 확신 부족 시 억지로 확정하지 않는다. 틀렸다는 확인 후 수정 경로 또는 종료를 제공한다.
- 최초 실험의 질문 예산은 6~10개를 가설로 비교한다. 고정된 출시 기준은 아니다.
- 후속 구상: 한마디 조언(짧은 광고), 선택 풀이(영상 광고), 상세 점사(유료 결제). 명칭과 제공 방식은 사용자 구상이며 플랫폼 지원·정책·가격은 검증 전이다.
- 첫 추론 검증과 실제 광고·결제 구현은 구분한다. 사주 계산과 장시간 상담은 아직 확정하지 않았다.

## 핵심 가설과 반증

| 가설 | 관찰할 증거 | 반증 신호 |
| --- | --- | --- |
| 고민을 말하지 않는 시작이 흥미롭다 | 도움 없이 질문을 시작함 | 무엇을 해야 할지 몰라 포기함 |
| 질문이 추리에 도움이 되면서 자연스럽다 | 답변이 쉽고 질문 간 연결을 느낌 | 질문이 같은 뜻으로 반복되거나 정답을 직접 묻는다고 느낌 |
| 결과가 고민의 중심을 짚는다 | 최초 고민과 결과의 상황·갈등이 일치함 | 분야만 맞거나 누구에게나 맞는 말이라고 평가함 |
| 실패도 신뢰를 유지할 수 있다 | 틀림을 부담 없이 선택하고 수정 흐름 이해 | 틀렸는데 우긴다고 느끼거나 부정 응답을 피함 |
| 경험이 다시 해볼 만하다 | 자발적 재이용·공유 선택 | 의향만 긍정적이고 실제 행동은 없음 |

## 실제 사용자 검증 계획

1. 대표와 모집 대상·연락 범위를 확정한 뒤 성인 소규모 파일럿을 진행한다. 8~12명은 발견을 위한 모집 가설이며 통계적 성능 입증 표본이 아니다.
2. 참가자는 시작 전 자신의 고민을 개인 메모에 남긴다. 앱과 진행자는 추측 전에 그 내용을 받지 않는다. 연구 원문 제공은 선택 사항으로 분리한다.
3. 진행자는 답변을 유도하지 않는다. 도움 요청, 질문 오해, 정답을 드러낸 추가 설명, 중단 시점을 기록한다.
4. 결과 후 참가자가 최초 메모와 비교해 분야·상황·갈등 원인을 각각 평가한다. 고민을 공개하지 않고 일치 수준만 답할 수 있다.
5. ‘어느 문장이 맞았나’, ‘어느 질문에서 설문 같았나’, ‘남에게도 맞는 말 같았나’, ‘틀렸다고 누르기 편했나’를 묻는다.
6. 가능하면 별도 실험에서 일반적인 결과 문구와 추론 결과를 순서를 섞어 비교한다. 내부 선호만으로 추론 가치를 주장하지 않는다.
7. 문제를 수정한 다음 신규 참가자에게 재검증한다. 같은 참가자의 학습 효과를 구분한다.

## 측정 정의

| 항목 | 정의와 주의점 |
| --- | --- |
| 완주율 | 결과에 도달한 세션 / 시작 세션. 중단 이유와 함께 해석 |
| 질문 수·소요 시간 | 결과 또는 중단까지의 분포. 짧다고 무조건 좋은 것은 아님 |
| 일치 수준 | 맞음/일부 맞음/틀림/판단 어려움 및 분야·상황·갈등별 확인 |
| 구체성 | 실제로 맞은 문장을 특정할 수 있는지, 일반 문구와 차이를 느끼는지 |
| 설명 없이 추측 | 추가 설명 없이 진행한 세션을 따로 집계 |
| 재이용·공유 | 의향과 실제 버튼 행동을 구분. 공유 완료는 확인 가능할 때만 집계 |
| 불편·실패 | 오해한 질문, 불쾌한 단정, 범위 밖, 모순 답변의 사례 |

기본 분석에는 버전, 익명 세션 단위 진행 단계, 질문 개수, 결과 평가 정도만 제안한다. 고민·답변 원문 및 민감한 후보 ID를 기본 이벤트로 남기지 않는다. 구체 스키마는 개발·품질팀과 합의한다.

## 대표 결정사항과 다음 담당

- 대표: 첫 내부 후보 범위, 캐릭터의 강도, 파일럿 참가자 모집 방식 결정. 현재 문서의 제안은 확정 사항이 아니다.
- 추론팀: 제한된 후보로 어떤 구체성까지 구분할 수 있는지 검토하고 범위 밖 종료 조건 제안.
- 캐릭터팀: 동일 질문 의미를 보존하면서 설문 느낌을 줄이는 표현 제안.
- 개발팀: 설명 입력 없이 질문부터 점사·추가 풀이 선택까지 이어지는 흐름과 최소 이벤트 구현 계획.
- 품질팀: 일반적 위로와 실제 추론 성공을 구분하는 독립 평가 및 실패 경로 검토.
- 성장팀: 결과 내용 노출 없이 경험을 공유할 방법과 실제 행동 실험 설계.

미해결: 고민 분류의 구분 가능성, 적절한 질문 수, 범위 밖 비율, 실제 재미와 재사용 이유. 검증 이전에는 정확도나 사업 성공을 수치로 약속하지 않는다.
