# 앱인토스 전문팀 첫 검토

확인일: 2026-10-27. 공식 문서 검토이며 콘솔 생성·심사 제출·실기기 검증·고객 검증은 하지 않았다.

## 제품과 1차 판정

질문 답변을 바탕으로 마음과 고민을 짚고 마지막에 풀이·조언을 주는 AI 점사 서비스다. 게임이 아닌 비게임 등록을 제안한다. 이름은 미확정이며 `sibyl`은 현재 저장소·설정 식별자다.

확인한 오픈 정책과 서비스별 주의사항에서는 사주·운세 자체를 명시적으로 금지한 조항을 찾지 못했다. 이것은 허용 확정이 아니다. AI 점사 구성·생성 응답·수익화 UX를 담은 앱 설명과 실제 구현의 검토가 필요하다. [오픈 정책](https://developers-apps-in-toss.toss.im/intro/guide.md), [서비스별 주의사항](https://developers-apps-in-toss.toss.im/intro/caution)

## 등록과 MCP

공식 MCP 문서는 `miniapp_create`로 신규 미니앱 생성, 앱 상태 조회와 기본 정보 수정을 지원한다고 명시한다. 실제 실행에는 해당 도구가 현재 세션에서 제공되고 올바른 워크스페이스 권한으로 인증되어 있어야 한다. CLI 등록·로그인 성공만으로 이 세션에서 호출 가능한 상태라고 단정하지 않는다. [콘솔 MCP](https://developers-apps-in-toss.toss.im/guide/console-mcp.md)

개발 전에도 앱을 미리 등록할 수 있다. 등록은 출시 승인과 다르며 앱 정보·실제 번들 검토를 별도로 통과해야 한다. 사용자가 제공한 생성 화면상 `appName`은 수정 불가이므로 이름 후보와 구분해 정한다. [등록 가이드](https://developers-apps-in-toss.toss.im/guide/operation/console-workspace)

등록 설명 초안:

> 사용자가 몇 가지 질문에 답하면 AI 무당 캐릭터가 답변을 바탕으로 고민과 마음을 추론해 점사 형식의 풀이와 조언을 제공하는 비게임 서비스입니다. 기본 풀이 후 광고를 통한 추가 조언과 인앱 결제로 상세 점사를 제공합니다.

이 설명은 계획이며, 실제 구현·수익화 승인 상태에 맞춰 제출 전에 조정한다.

## 정책 적합성

| 항목 | 확인과 판단 |
| --- | --- |
| 생성형 AI | 처음 이용할 때 AI 활용을 알리고 생성 결과에도 명확히 표시해야 한다. 이름에 AI가 있다는 것만으로 충분하다고 보지 않는다. |
| 상담형 AI | 공식 AI 채팅·상담 요건에 위험 요청 필터링, 안전 응답, 문제 응답 수정/차단, 모델·프롬프트 변경 전 배포 검토가 있다. 현재 점사 흐름에 적용되는 세부 범위는 확인 필요. |
| 디지털 상세 점사 | 디지털 콘텐츠 결제는 앱인토스 인앱 결제 방식으로 설계한다. 외부 결제로 우회하지 않는다. |
| 광고 | 앱인토스 제공 전면형·보상형·배너로 한정한다. 외부 광고망을 별도 연동하지 않는다. |

근거: [서비스 오픈 정책](https://developers-apps-in-toss.toss.im/intro/guide.md). 위 사항은 정책을 설계에 적용한 판단이며 특정 앱의 승인 결과가 아니다.

## 세 가지 선택지의 구현 조건

| 선택지 | 플랫폼 검토 |
| --- | --- |
| 한마디 조언 — 짧은 광고 | ‘짧은’ 시간을 보장할 근거는 아직 없다. 전면형과 보상형 중 실제 제공 방식·광고 조건을 확인한 뒤 문구 확정. |
| 선택 풀이 — 영상 광고 | 자발적 광고 시청 후 기능을 여는 구조는 보상형 검토 대상. 보상 이벤트 확인 후 제공하고 실패·취소 경로를 설계한다. |
| 상세 점사 — 유료 | 1회 생성권인지 결과 소장 권한인지 정의한 뒤 상품 유형 결정. 가격·제공 범위·재조회·환불 및 지급 처리를 명확히 한다. |

광고·IAP 연동은 사업자 정보 등록과 정산 설정 절차가 있다. 계정의 완료 여부는 이번에 확인하지 않았다. [광고 안내](https://developers-apps-in-toss.toss.im/guide/monetization/in-app-ad.md), [IAP 안내](https://developers-apps-in-toss.toss.im/guide/monetization/in-app-payment.md)

SDK는 광고 환경에 따라 네트워크를 선택하고 광고 그룹으로 전면형/보상형을 구분한다. 확인한 API에는 파트너가 임의의 재생 초수를 지정하는 옵션이 보이지 않는다. ‘짧은 광고 vs 긴 영상’을 확정 상품처럼 약속하지 않는다. [광고 SDK](https://developers-apps-in-toss.toss.im/documentation/common/monetization/iaa/interstitial-rewarded-ad.md)

## 출시 전 검증

비게임 가이드는 예측 가능한 CTA·광고, 명확한 종료, 토스 내비게이션, 라이트 모드, 결제 결과 반영·취소·기기 변경 시 이용권 유지, 광고 후 복귀와 정상 보상을 요구한다. 현재 메모리 기반 데모만으로는 유료 점사 운영 준비가 완료되지 않았다. [비게임 가이드](https://developers-apps-in-toss.toss.im/checklist/app-nongame)

## 토스에서 통할지: 아직 가설

- 기회 가설: 긴 고민 입력 없이 시작하고 기본 풀이를 빠르게 받는 경험이 가벼운 진입에 맞을 수 있다.
- 위험 가설: 질문이 길거나 광고가 풀이를 끊으면 사용자가 이탈할 수 있다.
- 검증: 유입 대비 시작, 질문 완료, 기본 풀이 만족, 추가 선택 클릭, 광고 완료/실패, 결제 완료/취소, 실제 재이용을 분리한다.
- 금융 앱이라는 이유로 점사 수요가 있다고 추정하거나, 플랫폼 사용자 수를 우리 앱 유입으로 계산하지 않는다.
- 첫 결과를 읽은 뒤 선택지를 자발적으로 고르는지 확인하고, 이후 광고·유료의 수익과 생성 비용을 비교한다.

## 다음 작업

총괄·대표는 등록 이름/식별자와 서비스 설명을 확정한다. 전문팀은 실제 MCP 도구·워크스페이스 상태를 확인하고, 개발팀과 광고 방식·IAP 상품 권한을 구체화한다. 품질팀은 최신 비게임/AI 요건으로 점검한다. 출시 승인과 시장성은 아직 미확인이다.
