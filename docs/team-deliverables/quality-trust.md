# 품질·신뢰팀 첫 독립 검토

> 최신 사용자 방향 반영: 게임이 아닌 AI 점사 서비스다. 질문 뒤 고민을 짚는 풀이와 조언을 제공한다. 아래 기술·사업 설계는 미검증 초안이다. 서비스명은 ‘설화보살’, 소개 문구는 ‘마음을 짚는 AI 점집’으로 확정했다.

상태: 문서 검토 완료. 점사 코드 실행·실제 사용자 검증은 미수행이다. 아래 매트릭스는 향후 검증 계획이며 통과 결과가 아니다.

## 검토 범위

`AGENTS.md`, 제품·고객연구팀, 추론·데이터팀, 캐릭터·콘텐츠팀의 초기 산출물을 검토했다. 검토 시점에 개발팀·성장팀 산출물은 아직 포함하지 않았다. 현재 구현은 기존 상담 데모이며 목표 서비스의 성능을 판단할 수 없다.

## 확인된 설계 방향

- 최신 사용자 정의에 맞춰 질문 뒤 고민을 짚는 풀이·조언을 제공하는 AI 점사로 검토 기준을 수정했다.
- 내부 점수를 정답 확률로 표시하지 않고 불확실성과 실패를 인정한다.
- 캐릭터 문안과 추론 의미를 분리하고 사용자 평가와 합성 평가를 구분한다.

## 개발 전 해결할 사항

| 중요도 | 발견과 근거 | 조치·담당 |
| --- | --- | --- |
| 높음 | 추론 계약의 `evidenceAnswerIds`가 참조할 `Answer.id`가 없다 | 답변 식별자 또는 복합 키, 수정 후 근거 무효화 규칙 확정 — 추론·개발 |
| 높음 | 콘텐츠는 건너뛰기를 제공하지만 추론 `Answer.value`에는 이를 구분할 표현이 없다 | `unknown`과 별도 동작으로 보존하고 점수 비반영·재질문 정책 정의 — 추론·개발 |
| 높음 | 결과 피드백은 3종인데 제품 평가는 ‘판단 어려움’도 필요하다 | 화면 피드백과 연구 평가를 분리할지, 공통 값으로 둘지 합의 — 제품·개발 |
| 높음 | 콘텐츠 예시 Q04가 최종 결론을 직접 묻는다. 문서도 재진술 수준임을 인정한다 | 예시를 추론 성공 사례로 사용하지 말고 직접 확인 정보와 추론 정보를 분리 평가 — 추론·제품 |
| 높음 | 후보 밖 보류의 방향은 있으나 증거 적합도·임계값 정의는 미정이다 | 알려진 후보 사이의 상대 점수만으로 확정하지 않는 기준선과 독립 사례 마련 — 추론 |
| 보통 | 제품은 관계·일/진로를 예시로, 추론은 관계를 첫 범위로 제안한다 | 첫 후보 범위와 사용자에게 알릴 지원 범위 확정 — 총괄·대표 |
| 보통 | 질문 예산, 추측 횟수와 답변 수정 후 처리의 구체 정책이 미정이다 | 예산 소진·일부 일치·거절·수정의 상태 전이 계약 확정 — 제품·추론·개발 |

위 항목은 설계 미결정 사항이다. 아직 존재하지 않는 구현의 결함으로 보고하지 않는다.

## 평가 매트릭스

모든 행의 현재 상태는 **미실행**이다. 기대 결과는 검증 기준 초안이다.

| 영역 | 평가 사례 | 기대 결과·판정 |
| --- | --- | --- |
| 구체성 | 결과를 일반적 위로 및 질문의 단순 재진술과 비교 | 어떤 상황·갈등을 추가로 짚었는지 구분; 새 사실 날조는 실패 |
| 정확도 | 지원 후보별 포함·제외·경계 사례 | 맞음/부분/틀림/판단 어려움을 분리, 분모·버전 보고 |
| 모순 | 서로 상충하는 답변 후 이전 답 수정 | 사용자를 탓하지 않고 상태 재계산; 낡은 근거로 결과 생성 금지 |
| 복합 | 한 사용자가 두 고민의 특징을 함께 가짐 | 구분 질문 또는 복합·보류 처리; 강제 단일 확정 금지 |
| 범위 밖 | 후보 목록에 없는 고민으로 응답 | 최고 상대 점수만으로 확정하지 않고 보류 가능 |
| 불확실 | 전부 모름 또는 대부분 건너뛰기 | 근거가 축적되지 않고 예산 내 정상 종료 |
| 오답 | 첫 추측을 명시적으로 거절 | 같은 후보 반복 금지, 재시도·종료 선택, 실패 책임 전가 금지 |
| 부분 일치 | 일부만 맞는다고 응답 | 성공과 합산하지 않고 추가 질문 또는 종료 |
| 의미 변경 | 중립 질문과 캐릭터 문장을 독립 역해석 | 주체·시점·강도·부정·답변 방향 일치 |
| 실행 중 생성 | LLM 사용 시 오류·형식 위반·의미 이탈 | 승인 문안 대체, 새 후보·질문을 임의 삽입하지 않음 |
| 개인정보 | 네트워크 요청·분석 이벤트·오류·공유 출력 검사 | 원문과 민감 후보/질문 ID 기본 수집 없음; 비밀키 클라이언트 미노출 |
| 조작성 | 중복 클릭·뒤로 가기·중단·새 점사 시작 | 답변 중복 반영과 세션 간 상태 혼합 없음 |
| 점사와 추가 이용 | 무료 점사 후 추가 풀이 선택 | 정답 확인 강제 없이 점사를 읽으며, 광고·결제 조건과 제공 내용을 이해함 |

## 평가 운영

1. 데이터·질문·문안·코드 버전을 고정하고 평가 대상과 미지원 범위를 기록한다.
2. 후보 제작자와 독립적으로 경계 사례를 작성하고 학습/튜닝 사례와 분리한다.
3. 자동 시나리오는 엔진 재현성과 예외 경로를, 수동 이용 검토는 이해도·조작을 확인한다.
4. 실제 사용자는 먼저 개인적으로 고민을 기록하고 결과 뒤 일치와 구체성을 평가한다. 원문 공개를 강요하지 않는다.
5. 합성 통과율, 실제 사용자 일치율, 재미와 재사용 행동을 별도로 보고한다.
6. 발견별 영향·재현 절차·담당·재검증 상태를 기록한다. 실행 전에는 정확도 목표를 달성했다고 표현하지 않는다.

## 다음 담당과 미해결

- 총괄: 위 설계 차이를 통합하고 단일 계약 버전을 지정한다.
- 추론·개발: 식별자, 건너뛰기, 수정, 결과 피드백, 보류의 데이터와 상태 계약을 확정한다.
- 제품·콘텐츠: 재진술과 구체적인 추론을 구분하는 평가 및 이해 가능한 표현을 확정한다.
- 품질팀 후속: 구현을 받은 뒤 매트릭스를 실행하고 실제 결과를 별도 기록한다.
- 미해결: 성능·재미·질문 수·범위 밖 비율. 현재 문서로는 어느 항목도 실증하지 못했다.
